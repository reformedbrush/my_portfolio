E-commerce / web

TechSHACK

Overview

TechSHACK is a college e-commerce site for computers, gaming PCs, and hardware. The repository includes guest, shopper, and admin areas, plus a database folder.

Purpose

Give a shopper a way to browse products, keep a cart, place an order path, and raise a complaint, with separate admin pages.

Technologies

PHP, MySQL, HTML, CSS, Bootstrap, JavaScript, jQuery, and Ajax. The resume also lists OAuth 2.0 for login. Local setup in the repository README uses XAMPP.

My contribution

Team leader. I designed the interface, payment mockups, and the backend for inventory and orders.

Architecture

Browser pages in PHP read and write MySQL. Guest, user, and admin code sit in separate folders.

Features present in the repository

  • Product listing and a product detail page.
  • Search page.
  • Cart, booking, and payment pages in the user area.
  • Complaint submission and complaint history.
  • Ratings, profile edit, and password change pages.
  • A session check that sends users to login when no user id is set.

Security considerations

User pages start a PHP session and redirect when the user id is empty. That is a basic gate, not a production security review. The payment page is part of the flow; a live payment provider is not confirmed here.

Mobile

N Sync

Overview

N Sync v2 is three Flutter applications in one repository: student, faculty, and admin. An earlier repository on the same account describes it as a campus tool for events and clubs.

Purpose

Let each role sign in and work with campus events, clubs, and records that match that role, instead of one shared screen for everyone.

Technologies

Flutter, Dart, and supabase_flutter 2.8.x, confirmed in the student app pubspec.

My contribution

The code is published on this GitHub account. The README files in the app folders are still the Flutter template, so individual versus team credit is not documented.

Architecture

Each Flutter app talks to Supabase for email-and-password sign-in and for table reads.

Screens confirmed in the source

  • Student: login, registration, home, events, event details, my events, clubs, newsletter, feedback, profile.
  • Student login calls Supabase sign-in, then checks tbl_student for an active status.
  • Faculty: login, home, host event, club, department, students, participant list.
  • Admin: login, students, faculty, departments, clubs, events, class assignment, complaints, newsletter, requested events, profile, settings.

Security considerations

Student sign-in is Supabase email and password, followed by a status check on the student row. The “get new password” control on the student login screen has an empty handler in the file that was reviewed, so password reset is not treated as done. Access is split by shipping a separate app per role.

Community Garden Manager

Overview

Assessment 2 for IFN636 Software Life Cycle Management at QUT. The app lets community garden members manage plots, request help, and join events, with an admin side for the same records.

Purpose

Replace informal garden coordination with accounts, plot bookings, a request workflow, and event registration.

Technologies

React, React Router, Axios, Node.js, Express, MongoDB Atlas, Mongoose, JWT, GitHub Actions, Vercel, and AWS EC2 with PM2, as named in the README.

My contribution

The README names four teammates, including me. On the resume I record this work as using JIRA for sprints, translating stakeholder needs into the solution, implementing GitHub Actions for build and deploy, and deploying the API on AWS EC2. The product features below are the team's.

Architecture

The README describes a React client, an Express API, and MongoDB, with separate deploy targets.

Features documented by the team README

  • Registration, login, JWT, and admin or user roles.
  • Plot viewing, booking, and cancellation.
  • Garden requests with pending, approved, rejected, and completed states.
  • Events with registration, plus admin create, update, and delete.
  • Admin and user dashboards.

Security considerations

The README documents JWT authentication and role checks. Demo account details from that README are left off this page. It does not say which of that auth work was mine.
